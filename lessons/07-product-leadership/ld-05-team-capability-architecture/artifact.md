# Artifact template · Capability portfolio

The tutor fills this in with the learner, using only capabilities the learner
has actually seen demonstrated. Never score a person from impression. Where the
learner has not seen someone do the thing, the entry is `<unknown>`, not a
number in the middle of the scale.

This artifact has two audiences and they must not be confused. The team-level
view is shareable. The individual depth table is a dated working hypothesis and
must be labelled as one, because a guess about a person is read as a verdict on
a person.

Delete the guidance in parentheses in the finished artifact.

## Quality bar

Before saving, check all six exposures are present. Name any that are missing
rather than filling them in yourself:

| Exposure | Present when |
|---|---|
| Choice | Each gap has one named instrument — develop, hire, or interface — not a combination that avoids choosing |
| Evidence | Every depth score names the artifact or decision it was based on, and unseen capabilities read `<unknown>` |
| Uncertainty | Individual assessments are dated and labelled as hypotheses, not evaluations |
| Alternatives | The hire specification names what it is deliberately not hiring for, and the accepted shortfall is written down |
| Owner | Each gap closure has an owner and a date; each interface has a named person, latency, and evidence standard |
| Revision trigger | The portfolio states the strategy change that would make this the wrong list |

One further test specific to this artifact: read the hire specification aloud
and ask whether it describes a slightly better version of you. If it does, it is
a capacity request, not a capability decision.

Tell the learner they can stress-test this with `review-artifact`.
